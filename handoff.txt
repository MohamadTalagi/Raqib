2. THE REQUEST, AND THE REASONING BEHIND THE CHOSEN APPROACH
================================================================================

This is a direct follow-up to the "Device-Fingerprint CVE Lookup" feature
(TEST-DEVICE-ID + TEST-DEVICE-CVE-LOOKUP, built 2026-08-06, fully documented
in CLAUDE.md §0 and `docs/vulnerability-intelligence.md`'s "Device-level CVE
lookup" section). That feature itself was the resolution of an earlier
request ("can we make it such that it gets the firmware and vendors from
fingerprinting and it does web-based firmware grabbing") that was explicitly
declined — no uniform vendor download index exists, real ToS/redistribution
risk, and this lab's fixtures don't run real vendor firmware anyway, so
Grype-scanning a real downloaded binary would produce results disconnected
from what's actually running. NVD CPE matching (vendor+model+firmware
version, no binary) was built instead.

**This session's request, the owner's own words:** *"The system should never
download the full firmware it should check online if theres a firmware
document or something of the sorts that check whether the firmware is old,
safe or not. Is something along those lines not possible? it could return
inclonclusive if nothing has been found and should give a conclusion if its
found."*

This is a genuinely different, more tractable ask than either prior one — it
explicitly rules out downloading the binary (already the existing
architecture's rule) and asks for a *document check* with an honest
inconclusive/conclusive split (already this whole project's dominant
evidence-honesty convention). The question was answered directly, then
investigated live rather than answered from general knowledge:

**Why literal "scrape each vendor's own advisory/EOL page" does not
generalize** (checked live, via WebSearch, across all 7 real vendors this
lab's fixtures are branded as — Hikvision, Axis Communications, Yale/Assa
Abloy, Schneider Electric, Netgear, Dahua, Sonos):

| Vendor | What's actually published | Machine-readable? |
|---|---|---|
| **Schneider Electric** (Modicon M221) | Advisories in real **CSAF JSON** format, also republished by CISA's ICS-CERT feed | **Yes** |
| Netgear (R7000) | Consistent HTML tables per advisory | Only via bespoke HTML scraping, no API |
| Hikvision, Axis, Dahua, Sonos | Advisory pages exist, format varies per advisory, some PDF-only | Only via bespoke, fragile per-vendor scraping |
| Yale / Assa Abloy | No public firmware-version advisory page found at all | Not available |

Building a scraper for the 6 non-Schneider vendors would repeat the exact
mistake the original firmware-grabbing idea made — no uniform source, one
bespoke parser per vendor, breaks the moment a page is redesigned — just for
text instead of binaries. Legally much safer (reading a public page carries
none of the redistribution risk a firmware binary does), but not more
*robust*.

**The actual answer, found by re-reading what the existing feature already
fetches, not by inventing a new source:** `TEST-DEVICE-CVE-LOOKUP`'s existing
NVD fetch already returns full CVE records — and NVD's own CVE records
carry structured, per-CPE-match **version-range fields**
(`versionStartIncluding`/`versionStartExcluding`/`versionEndIncluding`/
`versionEndExcluding`). This data already *is* "a real document that states
which firmware versions are affected and which are fixed" — it is simply
being thrown away today. `nvd_lookup.py`'s `_summarize_cve()` trims it out,
and the collector's own existing note in `_parse_device_cve_lookup_observations`
admits the resulting gap out loud: *"CPE matching here is product-level...
a listed CVE may already be fixed in the running firmware."* Using this
data needs **zero new external source, zero new network call, zero new
scraper** — only parsing more of a response already being fetched and
cached — and it covers all 7 of this lab's CPE-mapped devices uniformly,
unlike vendor-page scraping which only works for one.

**The owner was asked directly** (AskUserQuestion, after this research) which
direction to build: "NVD version-range comparison only" vs. "both NVD
version-ranges plus a Schneider CSAF bonus" vs. "vendor-page scraping only."
**The owner chose "Both."** This handoff's plan therefore covers two
sub-features:
- **(A) NVD version-range comparison** — primary, covers all 7 CPE-mapped
  devices, zero new external source.
- **(B) Schneider Electric CSAF advisory check** — secondary bonus, covers
  only `device-plc-gateway` (Modicon M221), the one vendor in this lab with
  a genuinely structured, machine-parseable advisory feed.

```python
def _parse_device_cve_lookup_observations(target: dict, output: str) -> dict:
    """Three genuinely different outcomes, each reported as itself and never
    blurred into "no CVEs found":
      - identity unknown       -> nothing to look up yet, run TEST-DEVICE-ID
      - identity known, no CPE -> this product has no NVD CPE coverage
      - CPE matched            -> a real (possibly empty) CVE list
    """
    def _line(name: str) -> str | None:
        match = re.search(rf"^{name}=(.*)$", output, re.MULTILINE)
        return match.group(1) if match and match.group(1) else None

    vendor = _line("vendor"); model = _line("model")
    firmware_version = _line("firmware_version"); cpe = _line("cpe")
    cpe_matched = "cpe_matched=True" in output

    cves: list[dict] = []
    raw_cves = _line("device_cves")
    if raw_cves:
        try:
            cves = json.loads(raw_cves)
        except json.JSONDecodeError:
            cves = []

    index_available = "index_available=True" in output
    error = _line("error")

    kev_listed = [c for c in cves if c.get("kev_listed")]
    highest_cvss = max((c["cvss"] for c in cves if c.get("cvss") is not None), default=None)

    notes: list[str] = []
    if error:
        notes.append(f"Could not read this device's inventory record: {error}")
    elif not (vendor and model):
        notes.append("This device has no vendor and model recorded yet...")
    elif not cpe_matched:
        notes.append(f"No CPE mapping is available for {vendor} {model}...")
    elif not index_available:
        notes.append("This device's product IS mapped to a CPE, but the local NVD cache has not been populated yet...")
    elif not cves:
        notes.append(f"NVD has no published CVEs for {vendor} {model} at this CPE. This is a real checked result, not missing data.")
    else:
        notes.append(f"{len(cves)} CVE(s) are published against {vendor} {model} at the device level...")
        if kev_listed:
            notes.append(f"{len(kev_listed)} of them are on CISA's Known Exploited Vulnerabilities catalog...")

    return {
        "vendor": vendor, "model": model, "firmware_version": firmware_version,
        "cpe": cpe, "cpe_matched": cpe_matched, "device_cves": cves,
        "total_device_cves": len(cves), "kev_listed_device_cves": len(kev_listed),
        "highest_device_cvss": highest_cvss, "notes": notes,
    }
```

```python
NVD_CVE_API_URL = "https://services.nvd.nist.gov/rest/json/cves/2.0"
NVD_CACHE_PATH = Path(os.environ.get("NVD_CVE_CACHE_PATH",
    os.path.expanduser("~/.cache/grype/db/nvd-device-cves.json")))
FETCH_TIMEOUT_SECONDS = 30
REQUEST_INTERVAL_SECONDS = float(os.environ.get("NVD_REQUEST_INTERVAL_SECONDS", "6"))
RESULTS_PER_PAGE = 2000

def _headers() -> dict:
    api_key = os.environ.get("NVD_API_KEY")
    return {"apiKey": api_key} if api_key else {}

def _summarize_cve(item: dict, kev_index: dict) -> dict:
    """Trim one NVD vulnerabilities[] entry ... Prefers CVSS v3.1, falls back
    to v3.0 then v2, reports None rather than guessing when NVD published no
    score at all."""
    cve = item.get("cve") or {}
    cve_id = cve.get("id")
    if not cve_id:
        return {}
    descriptions = cve.get("descriptions") or []
    summary = next((d.get("value", "") for d in descriptions if d.get("lang") == "en"), "")
    metrics = cve.get("metrics") or {}
    cvss = None
    for key in ("cvssMetricV31", "cvssMetricV30", "cvssMetricV2"):
        entries = metrics.get(key) or []
        scores = [e["cvssData"]["baseScore"] for e in entries if (e.get("cvssData") or {}).get("baseScore") is not None]
        if scores:
            cvss = max(scores); break
    kev_entry = kev_index.get(cve_id)
    return {
        "id": cve_id, "cvss": cvss, "summary": summary,
        "kev_listed": kev_entry is not None,
        "kev_date_added": kev_entry["date_added"] if kev_entry else None,
    }
    # <-- THIS IS WHERE §6.2's new `version_range` key must be added, and this
    #     function must gain a `cpe_prefix` parameter to compute it.

def _fetch_one(cpe_prefix: str, kev_index: dict) -> list[dict] | None:
    """cpe_prefix is "part:vendor:product" e.g. "o:netgear:r7000_firmware";
    NVD's virtualMatchString wants a full cpe:2.3 string, truncated after the
    product - product-level (all versions), not exact-version."""
    virtual_match = f"cpe:2.3:{cpe_prefix}"
    url = f"{NVD_CVE_API_URL}?virtualMatchString={quote(virtual_match, safe='')}&resultsPerPage={RESULTS_PER_PAGE}"
    try:
        response = requests.get(url, headers=_headers(), timeout=FETCH_TIMEOUT_SECONDS)
        response.raise_for_status(); data = response.json()
    except (requests.RequestException, ValueError):
        return None
    if "vulnerabilities" not in data:
        return None
    summarized = [_summarize_cve(item, kev_index) for item in data["vulnerabilities"]]  # <-- pass cpe_prefix through here too
    cves = [c for c in summarized if c]
    cves.sort(key=lambda c: (not c["kev_listed"], -(c["cvss"] or 0)))
    return cves

def fetch_and_cache_device_advisories(cpe_prefixes: list[str]) -> bool:
    """One NVD query per distinct CPE prefix, paced by REQUEST_INTERVAL_SECONDS.
    Returns True only if every prefix succeeded; still atomically writes
    whatever DID succeed on partial failure. Never raises."""
    kev_index = cisa_kev.load_kev_index()
    index: dict[str, list[dict]] = {}
    all_ok = True
    for position, cpe_prefix in enumerate(sorted(set(cpe_prefixes))):
        if position:
            time.sleep(REQUEST_INTERVAL_SECONDS)
        cves = _fetch_one(cpe_prefix, kev_index)
        if cves is None:
            all_ok = False; continue
        index[cpe_prefix] = cves
    if not index and not all_ok:
        return False
    try:
        NVD_CACHE_PATH.parent.mkdir(parents=True, exist_ok=True)
        tmp_path = NVD_CACHE_PATH.with_suffix(".json.tmp")
        tmp_path.write_text(json.dumps({"advisories": index}))
        tmp_path.replace(NVD_CACHE_PATH)  # atomic swap
    except OSError:
        return False
    return all_ok

def load_device_advisories_index() -> dict:
    """Never raises. Empty dict on missing/corrupt cache = honest miss."""
    try:
        data = json.loads(NVD_CACHE_PATH.read_text())
    except (OSError, json.JSONDecodeError):
        return {}
    advisories = data.get("advisories")
    return advisories if isinstance(advisories, dict) else {}
```

```python
"""Compares a device's self-reported firmware_version against a version
range extracted from either an NVD CVE record or a Schneider Electric CSAF
advisory - never a guess. Every real-world firmware string in this lab
(see handoff.txt / docs/vulnerability-intelligence.md's "Firmware currency"
section for the live-verified table) carries a vendor prefix and/or a
trailing suffix, so this deliberately only compares the leading dotted-
numeric core, discarding everything else as a disclosed simplification -
never silently miscounted."""

import re

_LEADING_PREFIX_RE = re.compile(r"^[A-Za-z]+(?=\d)")
_NUMERIC_CORE_RE = re.compile(r"^\d+(?:\.\d+)+")
_TRAILING_LETTER_RE = re.compile(r"^([a-zA-Z])(?![a-zA-Z0-9])")


def parse_version(raw: str | None) -> tuple[int, ...] | None:
    """Returns None (never a guess) if no dotted-numeric core can be found
    at all - e.g. a bare date-style build string like "210628" with no dot."""
    if not raw:
        return None
    text = _LEADING_PREFIX_RE.sub("", raw.strip())
    match = _NUMERIC_CORE_RE.match(text)
    if not match:
        return None
    core = tuple(int(p) for p in match.group(0).split("."))
    remainder = text[match.end():]
    letter_match = _TRAILING_LETTER_RE.match(remainder)
    if letter_match:
        ordinal = ord(letter_match.group(1).lower()) - ord("a") + 1
        return core + (ordinal,)
    return core
```

**Note on the "unbounded → outdated?" nuance** (flagged for extra care during
implementation, not fully settled by this planning pass — see §7 item 4): a
CVE with NVD's "every version is listed as vulnerable" shape (no
`versionEnd*` field at all, §5.3's Hikvision case) genuinely means "this
product has an unpatched-by-version-boundary vulnerability" — arguably that
*should* count toward `outdated` too, since there's a real, unaddressed CVE
and no fix version was ever published to be below. The rollup rule above
deliberately does NOT count it toward `outdated` (only a real, comparable
boundary does) to stay conservative and avoid conflating "NVD never
version-scoped this CVE" with "we compared your version and it's behind."
**This exact judgment call should be revisited with the owner during
implementation** if it produces a counter-intuitive result live (e.g.
Hikvision's device staying `unknown` despite having a real, unbounded,
definitely-affecting CVE) — reasonable people could design this either way,
and it wasn't put to the owner explicitly this session.

--------------------------------------------------------------------------------
9.1 §7 item 4 RESOLVED — a fourth status, `affected_no_fix`
--------------------------------------------------------------------------------
§6.1's closing note asked for this judgment call to be revisited "if it
produces a counter-intuitive result." It does, for HALF the fleet.

Simulated against real NVD data and every fixture's real firmware string:

| Device | CVEs matched to its CPE | Under §6.1's rule |
|---|---|---|
| device-router-gw (Netgear) | 117 not_affected, 12 affected, 9 unbounded | outdated |
| device-plc-gateway (Schneider) | 9 not_affected, 7 unbounded | current |
| device-insecure (Hikvision) | 1 unbounded | **unknown** |
| device-smartlock (Yale) | 1 unbounded | **unknown** |
| device-speaker (Sonos) | 5 unbounded | **unknown** |

Hikvision's single unbounded CVE is CVE-2021-36260 — KEV-listed and actively
exploited. Reporting "unknown" for that is the weakest possible answer and
actively misleading.

**Owner's decision (asked explicitly, per §7 item 4): add a fourth status.**
  outdated         a fix exists and the device is behind it
  current          no CVE affects it at any known boundary
  affected_no_fix  a real CVE affects ALL known versions; upgrading won't help
  unknown          could not determine

This keeps §6.1's core discipline intact — an unbounded CVE still never
counts as `outdated`, because "no fix was ever published" is genuinely not
"you are behind a fix" — while refusing to hide a real finding behind
"unknown." `rollup_firmware_currency`'s precedence: outdated > affected_no_fix
> unknown > current. `current` remains the hardest status to earn, which is
correct for a security tool: a false "you're safe" is the worst failure mode.

--------------------------------------------------------------------------------
9.2 BUG in §6.1's parse_version — it returns None for a real fixture
--------------------------------------------------------------------------------
`_LEADING_PREFIX_RE = r"^[A-Za-z]+(?=\d)"` only strips letters IMMEDIATELY
followed by a digit. Axis's real firmware string is `"AXIS OS 11.11.100"` —
the space defeats it, `_NUMERIC_CORE_RE.match` then fails, and the function
returns None.

§5.2's table never recorded Axis's actual string (it wrote "(hardware-only
CPE, no `_firmware` product)" in that column instead), so the regex was never
designed against it. This is precisely what §7 item 7 asked to be checked.
Fix: find the first dotted-numeric run anywhere in the string rather than
requiring it at position 0, after stripping a leading alphabetic prefix.
All 7 real strings are literal unit-test cases.

--------------------------------------------------------------------------------
9.3 §7 item 1 RESOLVED — and Axis can never resolve, structurally
--------------------------------------------------------------------------------
Real `cpeMatch` shapes, all 7 prefixes fetched live:

| CPE prefix | CVEs | bounded | unbounded | notes |
|---|---|---|---|---|
| o:netgear:r7000_firmware | 139 | 130 | 9 | mostly versionEndExcluding |
| o:schneider-electric:modicon_m221_firmware | 16 | 9 | 7 | |
| h:axis:m3216-lve | 6 | 0 | 0 | **all 6 are `vulnerable: false`** |
| o:hikvision:...-i\(s\)_firmware | 1 | 0 | 1 | |
| o:hikvision:...-iu_firmware | 1 | 0 | 1 | |
| o:assaabloy:yale_conexis_l1_firmware | 1 | 0 | 1 | |
| o:sonos:one_firmware | 5 | 0 | 5 | |

**Axis has ZERO `vulnerable: true` matches for its own CPE.** A hardware
(`h:`) CPE is only ever the AND-node partner of a firmware CPE; the vulnerable
side is a different product entirely. So this feature is structurally a no-op
for `device-hardened`, no matter how the parser behaves. That must be
reported as its own honest reason ("this product is catalogued only as a
hardware CPE, which carries no version ranges"), never as a generic failure.

Also confirmed: a real boundary value can itself carry a suffix
(`versionEndIncluding: "1.0.7.2_1.1.93"` on Netgear), so the
discard-the-suffix simplification applies to BOTH sides of the comparison,
not just the device's own string. §6.9's disclosure must say so.

--------------------------------------------------------------------------------
9.4 §7 items 2/3 RESOLVED — CSAF covers exactly one advisory, one CVE
--------------------------------------------------------------------------------
§7 item 2 suspected the advisory table "almost certainly under-covers." It
does not, at least not via CISA's mirror. CVE-2024-11737 — the other Modicon
M221 CVE this project already cites in `docs/device-vendor-realism.md` — has

(`SEVD-2024-345-03.pdf`). There is no CSAF/ICSA JSON for it.

So sub-feature (B) delivers: **1 advisory, 1 CVE (CVE-2018-7789), 1 device.**
That is worth stating plainly in the docs rather than implying broader
coverage. §6.3's `SCHNEIDER_M221_CSAF_ADVISORY_IDS = ["ICSA-18-240-02"]`
stands as-is — not because the table is complete, but because it is the
complete set of *machine-readable* advisories that could be verified.

§7 item 3: the year-derivation URL logic (`ICSA-18-240-02` → `2018`) was
confirmed against three further real advisory IDs from different years. It
holds. Guessing advisory IDs, however, is worthless — two plausible-looking
